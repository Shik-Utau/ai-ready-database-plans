# Proposal

状态：讨论稿，待业务审阅。更新日期：2026-11-09。
本提案汇总已知方向，不表示三条业务线已完成决策或实现。规格中的 SHALL 描述拟约定的目标行为。

## Why

AI-ready Database 的主动操作、计算前查询与计算后采集需要形成可共同审查的约定，避免协作者只能通过代码、原型或聊天猜测目标。独立规划仓库让大家在实现之前讨论范围、行为及验收方式，并明确当前证据与未决问题。

## What Changes

- 2026-11-09 用户接受反馈 1、2、5：精简原型信息、减少防御性功能展示，移除字段导出与 JSONL 导出。当前审阅附件以查询、备注、结构导出为主，保留独立保存入口；POSCAR 为本版候选格式。

- 2026-11-08 按用户要求增加[主动操作审阅原型](../../../docs/prototypes/explicit-operations/README.md)：可离线打开的 MatCreator 风格 HTML，供他人体验四类操作。此项授权仅发布审阅附件，不将模拟行为升级为已确认需求或生产实现。

- 明确三种入口：用户主动操作 AIDB；取得计算条件后查询已有候选；读取 VASP 结果时尝试采集。共享数据能力，不混用触发条件。
- 主动操作按已确认的四类组织：查询与浏览、导入与归档、导出与交付、记录维护（修改、删除）。每类的具体输入输出与完成标准继续审阅。
- 计算前查询优先查准率；无符合条件数据则继续原计算业务，有候选供用户判断，不因命中自动取消计算。
- 计算后优先评估读取、转换、查重、插入、读回组成一个入口；必须区分入口内必定尝试采集、全宿主路径必定进入入口、完整入库成功。
- 形成与代码仓库分离的提案、场景、设计与任务清单；不导入应用代码、数据样本、旧原型或历史队列方案。
- 明确阻塞决策：字段与保真要求、复用判定、修改/删除边界、故障策略、自动触发覆盖和跨入口职责。

## Capabilities

### New Capabilities

以下为本规划仓库首次建模的能力，不表示底层软件过去没有这些功能。

- `aidb-explicit-operations`：主动操作四类入口及其与自动流程的边界。
- `aidb-precompute-lookup`：候选查询、匹配证据与计算决策的关系。
- `aidb-result-collection`：结果读取与采集尝试的关系，以及采集证据与覆盖范围。

### Modified Capabilities

无；本仓库尚无已接受的主规格。

## Impact

- 本仓库改变规划文档及明确授权的 HTML 审阅附件。AIDB 底层能力、现行 ai-ready-db skill 和未来宿主集成是潜在实施对象，不在本轮修改。
- MatCreator 是现有讨论中的宿主背景，不是本仓库的源码内容；本仓库不向其远程提交任何修改。
- 不自动继承旧架构、旧规范或原型通过记录。原研究已完成不代表业务方案已获批准。
- 实施仓库、基线提交、接口改动及兼容性需在实施前逐项确认。无生产发布承诺。

## Review focus

1. 三个入口的边界是否准确？四类主动操作的首批范围如何确定？
2. 哪些字段及其语义必须在往返后保持？缺失、失败、未知如何表达？
3. 哪些场景足以判定候选可复用、记录重复、完整采集成功？
4. 谁维护共有转换和数据操作能力，谁负责宿主触发与用户反馈？
5. 哪些未决问题必须先解决，哪些可以独立形成后续变更？
