# 07 调研结论：能保存末态，完整归档仍有缺口

2026-11-09 · 对 2026-11-08 保存证据的简要说明。

07 的字段能力调研可以验收；02 的归档目标仍待确认。此前复核了原始 JSON、复现脚本及关键源码，15 个来源文件和 XML 的指纹匹配；本轮没有重跑数据库实验。

| 问题 | 已有证据及影响 |
| --- | --- |
| 保存成功不等于全部相同 | 当前 insert/query 能存取真实 Si 的主要末态。38 字段中 3 项变化，涉及结构指纹、展示式和来源管理键；结构字典本身相同。成功回执只核对规定字段。 |
| 换读取入口可能丢失数值含义 | 正常 query 补回应力单位与正负约定；底层 get_record 缺失这些标签。相同数值不能在缺少单位时直接解释。 |
| 只有最后一步 | XML 有 3 个离子步，库里只保存末态，没有完整轨迹和原文件包。不能仅凭该记录恢复全过程，原工作区文件并未被删除。 |
| 空值掩盖了存储缺项 | 全部 38 字段非空的合成记录中，密度和 3 个关联 ID 读回为空；Si 中这些字段原本为空，看不出损失。 |

合成记录 30 项严格相同、8 项变化；其中还有浮点舍入、指纹/展示式变化、来源字典增加管理键，不能把 8 项都称为科学数据丢失。旧 finalize 因 dft_u=None 失败，属于另一入口，不否定当前 insert 成功。

02 还需要确定：是否只归档末态、哪些缺项影响完成判定、采集被绕过或失败后如何补做。07 尚未证明所有计算结束都会自动触发采集，也未验证并发、中断恢复的一致性。

[原型](index.html)恢复完整场景和状态观察，通过逐步路线说明读取、保存、查询和字段比较的关系；每步注明作用和观察重点，失败、未采集和读取标签缺失仍可见。去重与故障恢复是候选编排的内存模拟，并非新实跑保证。

证据值嵌入 HTML，可在细节中查看。原始证据与状态模型指纹见 [provenance.json](provenance.json)；公开副本只替换个人目录及临时目录前缀，未更改数值。原始源码和数据库不随本附件发布，因此来源指纹用于识别版本，不构成独立复现实验包。
