# Design

状态：设计方向讨论稿。已确认方向与候选技术方案分开记录；本稿不能直接作为生产实施授权。

## Context

2026-11-08 用户授权将现有主动操作原型发布到本仓库，作为下述原有文本范围的明确补充。附件位于 [docs/prototypes/explicit-operations](../../../docs/prototypes/explicit-operations/README.md)，保留自包含交互和最小演示材料，移除个人路径，不迁入实际数据库或后端脚本。当前附件恢复四类入口，重点是主动入库与候选展示。发布供审阅，B1、B3、B5 保持待决。

动机见 [proposal.md](proposal.md)。已有讨论与原型位于独立工作区，本仓库只提炼文本，不复制代码或实验数据。现状摘要及来源标识见 [source-notes.md](../../../docs/source-notes.md)。

主动操作四类框架已确认，具体范围未确定；计算前已有查准率与用户决策方向；计算后需要验证统一结果读取入口与实际宿主路径的关系。三条业务决策线仍未闭合。

## Goals / Non-Goals

**Goals:**
- 三个入口共享数据语义，分别定义触发依据与完成证据。
- 用具体输入、调用、输出与失败场景验收，而不是以按钮演示或文档完成代替验证。
- 提供独立可审阅的规划基线，让协作者先看目标和待决问题，再决定实施分工。

**Non-Goals:**
- 不在此仓库开发数据库或宿主实现，不运行生产计算、不迁移用户数据库。
- 不选定尚未证实的后台架构，不承诺并发、恢复、性能或全部字段保真。
- 不把旧 skill、旧规范或局部原型默认升级为当前标准。

## Decisions

### 待审阅：主动保存的条件与候选展示（2026-11-09）

- **主动保存**。现行 VASP 入口以计算目录、来源 ID 及可选的数据集名为输入。目录须有且仅有一份可解析的 vasprun.xml 或 vasprun.xml.gz，读取前后内容一致，能取得最终结构，电子与离子均收敛。原型回执展示写入条数、记录 ID、读回字段和标签缺项。缺力样例用于审阅入库门槛与 E+F 覆盖的区别。
- **查询**。摘要拟显示有效条件、命中范围、记录数、可核实帧数和 E+F／另有 virial 的帧数。详情拟复用入库读回的字段表达，分别说明结构与采样、标签方法与单位、自旋设置与磁性结果、来源和帧范围。严格条件下无法核实的记录只在显式放宽后列为候选，并说明差异。
- **证据**。只有一条隔离库读回的 Si 弛豫末帧及基于该结构的缺力模拟。严格晶相／温度查询、放宽及统计为原型交互。字段是否可查、可展示、可作为训练准入条件分别确认。跨入口复用及自动采集规则由 B3／B5 继续讨论。

### D5：主动操作原型先收敛主流程（历史版本，2026-11-09）

2026-11-09：用户接受师兄反馈中的 1、2、5：减少信息量、减少防御性功能展示、移除字段导出和 JSONL 导出。本版将默认体验收敛为查询 → 备注 → 导出结构；技术过程与状态折叠，故障开关和异常专项场景移出当前体验。删除保留在详情内。

POSCAR 是本版为结构导出选择的候选格式，尚不是用户确认的最终格式。主动查询 query 与保存 insert 分开；自动采集的触发覆盖仍由对应工单决定。本页不模拟自动导入。默认一条预置记录，另提供空库下主动保存的流程。

本版重复保存仅提示已存在，不执行覆盖，这是聚焦主流程的原型简化，不是已修复现有重导入覆盖备注问题。旧实验和旧版本仍作为历史证据保留，不因隐藏异常演示宣告问题解决。

这三项已获用户接受，确认范围限于当前原型；不把“减少防御性展示”解释为删除生产所需的正确性检查。B1 的其余操作边界、B3 字段完整性和 B5 职责继续待决。

### D1：三个入口分开描述，共享能力按证据复用

方向依据：主动请求不应被自动流程条件约束。建议将意图组织、可复用数据操作与宿主触发作为需明确的职责，而不是先锁定代码模块。

替代：以一个综合状态机统一约束所有入口。当前不采用此默认，因为各入口前置条件不同，旧综合原型也未获认可。具体职责边界需完成 B1。

### D2：计算前以可说明的匹配依据支持用户决策

查准率优先、零命中继续、命中不自动取消计算属于既有方向。请求条件与实际输入条件的优先级、字段集合及赝势比较属于 B2，当前不替团队决定。

替代：化学式命中即复用。与已确认方向不符。

### D3：计算后优先评估统一结果读取脚本

将读取、转换、查重、插入和读回放进同一入口，可以讨论入口内的固定采集尝试。替代为仅在 skill 文字中提醒采集，或额外后台架构；前者不能据此证明调用覆盖，后者尚未选定。此项为候选技术方案，仍需 B3/B4 的宿主与失败验证。

### D4：文档版本与证据单独追踪

规格记录拟达到的行为，研究摘要记录看到的现象，业务确认通过审阅记录体现。来源资料仍由原负责人维护，本仓库不接管其认领或关闭状态。

## Blocking Decisions

以下问题会影响行为或实施方案，**必须在相应实施交接前解决**，不是可随意推迟的细节。

| 编号 | 待决事项 | 需要的结论 |
|---|---|---|
| B1 | 四类主动操作的首批范围与职责 | 主动保存门槛和读回、候选摘要和详情、导入/导出格式、修改/删除边界、实际交付证据 |
| B2 | 查询时机、匹配与失效 | 有效条件来源、关键字段、缺失处理、数据库错误、时间预算、条件变化和任务退出 |
| B3 | 采集必需数据与完整性 | 必采字段、单位与来源、结构等价、关联 ID、轨迹及文件包范围、读回判定 |
| B4 | 触发保证与故障语义 | 哪些真实路径必须采集、失败如何反馈、重复/并发/恢复语义及证据边界 |
| B5 | 跨入口一致性与实施归属 | 共用能力契约、目标代码仓库与基准、负责人和联合验收计划 |

B1/B2/B3/B4 的讨论可在不存在真实依赖时分别进行；B5 汇总已有决定，不替三条线先行定案。

## Risks / Trade-offs

- [原型结果被当成已实现能力] → 单列证据来源、入口和未覆盖范围，禁止泛化。
- [主动与自动流程互相限制] → 分别验收触发与退出，共用能力不共用全部前置条件。
- [字段存在但语义丢失] → 按 B3 确认的字段、单位和来源验证往返，不只检查记录数量。
- [零命中与数据库错误混淆] → 单独讨论错误行为，不套用零命中路径作为默认决策。
- [两套规格或状态漂移] → 用来源摘要与文档 PR 显式同步，原任务状态不复制为新任务完成状态。

## Migration Plan

本轮没有生产迁移。讨论稿通过审阅后，由维护者明确接受的范围与仍未接受的部分；只有阻塞项解决后才在选定代码仓库另开实施变更。实现后以实际 PR 和测试证据回报本仓库，并按记录的归档约定更新主规格。

## 各线待决范围补充

### aidb-explicit-operations

首批导入与导出格式、实际交付数量的判定、修改覆盖规则、删除范围及确认步骤、完成证据、skill 与底层能力职责仍待确定。以上场景不赋予未经明确确认的写入或删除权限。

### aidb-precompute-lookup

取得什么条件才查询、是否以实际 VASP 输入为基准、逐字段匹配和赝势身份、数据库错误反馈、查询时间预算、条件变更后的候选失效、任务切换后的退出方式，均需基于样例继续确定。本稿没有选择固定界面或时间阈值。

### aidb-result-collection

统一入口如何成为宿主实际必经路径，失败后的提示与继续策略，必采字段、单位与关联语义、结构等价判定、文件包与轨迹范围、重复采集语义、并发一致性、重试和恢复规则均待确认。单脚本是优先评估方案，不预设后台任务或队列。
